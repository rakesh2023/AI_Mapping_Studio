Introduction

AI Mapping Studio

AI Mapping Studio is an AI-assisted tool designed to streamline source-to-target data conversion mapping for Guidewire implementations.

Users bring in a legacy source system and a target schema (CMT/PMT), and the platform leverages AI to:

  • Propose field-level mappings and transformation rules
  • Enable review and refinement of the suggested mappings
  • Generate the corresponding ETL SQL required to migrate data into the Staging Area and ultimately into the target system

This page provides a structured walkthrough of the end-to-end workflow. Users may follow the steps sequentially or navigate directly to any tool via the sidebar.

1

Legacy → Pre-Staging — extract data from the client's legacy source systems into the Pre-Staging Area. AI Mapping Studio helps identify the tables and fields relevant to the migration, while a standard ETL tool — such as Azure Data Factory (ADF), SSIS, Informatica or Talend — handles the physical movement of data from the legacy systems into the Pre-Staging database.

2

Pre-Staging → Common Stage — using the pre-staged tables as the source, populate the Common Stage. The Common Stage is a curated data model designed by experienced business analysts and developers to abstract away the complexity of the Guidewire structures (CMT/PMT), providing a stable, simplified foundation for conversion.

3

Common Stage → CMT/PMT — load the data from the Common Stage into Guidewire's CMT/PMT structures. A dedicated set of mappings is generated for this stage to align the Common Stage model with the target Guidewire schema.

In this architecture, the client's Source Systems — client-specific data such as policy, claims and customer information supplied as databases or files (CSV, XML, JSON) — are extracted into the Staging Zone (Pre Staging → Common Stage → CMT_IN) and subsequently loaded into Guidewire on the cloud. Guidewire's Cloud Migration Tool (CMT) reads CMT_IN and the Claims Migration Batch Process loads records into ClaimCenter and ContactManager; CDA (Claims Data Access) and Update Claim Number finalise the migrated claims, while CMT_OUT, Audit & Balancing Control and Payload Reconciliation verify that counts and values match end-to-end. AI Mapping Studio is where you define the source→staging→target field mappings and generate the ETL that powers steps 2 and 3.
